# BEP Fairy Tech ResoConverter

シーン上のアバター・3Dモデルを、Resoniteへ取り込める `.resonitepackage` に変換するUnity Editorツールです。

## 必要な環境

- Windows 64 bit / Unity 2022.3 LTS
- ローカルにインストールされたResonite本体
- VRChat SDK、Modular Avatar、NDMF、lilToonは任意です。未導入でもコンパイル・モデル出力ができます。

ResoniteのエンジンDLLを同梱せず、指定されたインストール先から読み込みます。変換用プロセスは別に起動され、Resoniteへのログインは不要です。

## 使い方

1. 配布された `BEP_ResoConverter-v0.3.4.unitypackage` をインポートします。公開済みの版は [Releases](https://github.com/Aoinasuko/BEP_ResoConverter/releases) から取得できます。配置先は `Assets/BEPFairyTech/ResoConverter` です。
2. `BEP Fairy Tech → ResoConverter` を開きます。
3. Hierarchy上の対象ルートを「変換対象」に指定します。Project内のPrefabアセットは対象にできません。
4. 「アバター」または「3Dモデル・アイテム」を選びます。
5. 必要に応じて瞬き用のメッシュとBlendShape、ハンドサイン・メニュー表情、サイズ、ポーズ固定を設定します。
6. Resonite本体のフォルダーを確認し、UnityのAssets外へ書き出します。
7. 出力された `.resonitepackage` をResoniteへドラッグ＆ドロップします。Windowsでは「成果物を文字列としてコピー」を押し、同じPCのResoniteでキーボードの `Ctrl+V` を使って取り込むこともできます。VRではDashの **Files** タブから出力ファイルを開いてください。

処理は一時コピーに対して行います。元のシーンやモデルアセットは書き換えません。

「成果物を文字列としてコピー」は変換ボタンの下にあり、変換に成功した最新の出力を対象にします。出力前は無効です。コピーされるのは `.resonitepackage` の**絶対ファイルパスそのもの**です。パッケージ本体を文字列化・Base64化したデータや、URIではありません。日本語・空白・絵文字を含むファイル名にも対応します。

同じPCで動くResoniteから取り込み、貼り付けが完了するまでコピー元の `.resonitepackage` を移動・削除しないでください。文字列だけを別のPCへコピーしても、モデルのデータは転送されません。

v0.1.2では文字列を読み取る貼り付け経路に対応するため、クリップボードへUnicode文字列だけを渡します。**Resonite標準Dashの `Paste content from clipboard` ボタンによる実機動作は未確認です。** 反応しない場合はキーボードの `Ctrl+V`、ドラッグ＆ドロップ、またはFilesタブを使用してください。

## 出力設定プリセット

v0.3.4では、ウィンドウ上部の「出力設定プリセット」で設定を保存・復元できます。

1. Hierarchy上の変換対象を指定し、表情・瞬き・サイズなどを設定します。
2. **新規保存…** を押して、プリセットの名前と保存場所を選びます。初期フォルダーは `Assets/BEPFairyTech/ResoConverterPresets` です。
3. 次回は変換対象を指定し、「プリセット」欄で保存したアセットを選んで **復元** を押します。選ぶだけでは設定は変わりません。
4. 設定を変更した後、同じプリセットに反映する場合は **上書き保存** を使います。別パターンとして残す場合は **新規保存…** を使ってください。

復元はUnityの `Edit → Undo` で戻せます。保存したアセットはUnityを閉じても残ります。

| 保存するもの | 内容 |
| --- | --- |
| 表情 | 左右の手形条件、AnimationClip参照、サンプル時刻、メニュー表示名、行順、ハンドサイン／コントローラー／メニューのON/OFF |
| 瞬き | 対象ルートからメッシュまでの相対階層とBlendShape名 |
| その他の出力設定 | アバター／アイテム、サイズ、保存制限、トゥーン影の濃さ、Modular Avatarの反映、ポーズ固定 |

変換対象のシーンオブジェクト、成果物の出力先、Resonite本体の場所は保存しません。Resonite本体の場所は復元時も現在のPCの設定を使います。口パク・視線・PhysBoneなど元アバターから読み取る設定や、シーンのポーズ自体はプリセットへ複製せず、変換時の対象から取得します。

瞬きは同じ階層構造の別の配置にも復元できます。メッシュ・BlendShapeが見つからなければ警告を表示してメッシュを未設定にし、保存したBlendShape名は保持します。同名の子が複数あり対象を特定できない場合は、現在の設定を変更せず復元を停止します。復元先のメッシュや名前を確認して再指定してください。

AnimationClipはアセット参照として保存し、クリップの内容は複製しません。クリップ未設定の行も保持しますが、一時的な未保存クリップがある場合は先にProject内へ保存する必要があります。後から削除されたクリップは、行・名前・時刻を保持して警告します。別プロジェクトへ移す場合は、プリセットだけでなく参照するクリップやFBXもUnityの依存アセットを含むパッケージなどで一緒に移してください。

保存先の初期フォルダーはツール本体の外にあり、ツールを更新・配布する際に個人のプリセットを混ぜません。プリセットを復元した後でアバターの変換を行います。

## 以前の版からの更新

v0.3.2ではPhysBoneの角度制限と、別PhysBone配下の除外を反映します。適用するには更新したツールで元のUnityシーンから再変換し、新しい `.resonitepackage` を取り込んでください。Resonite側への追加MODの導入は不要です。古い出力をコピーし直すだけでは、角度制限は追加されません。

旧版で作成した `.resonitepackage` は引き続き使えます。v0.3.0のコントローラー操作による手形切り替えや、ハンドサインが反応しない場合の修正を適用するには、v0.3.0以降をインポートし、元のUnityシーンから再変換してください。旧出力をコピーし直すだけでは、新機能や修正は反映されません。

v0.3.0では、指の追跡が有効でも位置情報が0になる入力を、未追跡と誤って判定する問題に対応します。表情用AnimationClipから指定時刻のBlendShape静止値を移す方式は従来どおりです。

v0.1.1では、出力したアイテムの当たり判定が空になり、掴めない場合がある問題を修正しました。メッシュの読込完了後に当たり判定を計算し、薄いモデルにも各軸の最低限の厚みを設定します。

v0.1で出力したアイテムを掴めない場合は、最新の `.unitypackage` をインポートしてから、元のUnityシーンで再度変換し、新しい `.resonitepackage` を取り込んでください。古いファイルの当たり判定は、コピーし直すだけでは修正されません。

## 設定

| 設定 | 動作 |
| --- | --- |
| アバター | ルートのHumanoid Animatorからリグを設定。VRCの視点、Viseme、Jaw Flapを可能な範囲で変換 |
| 3Dモデル・アイテム | アバター用の装着・IK設定を付けずに出力 |
| 他の人による保存を制限 | 初期値ON。ResoniteのSimpleAvatarProtectionを付与。OFFなら付与しない |
| 瞬き | 指定したメッシュのBlendShapeをResoniteの瞬き制御へ割り当て |
| 両手の形に合わせて表情を変える | 初期値OFF。左右の手形条件とAnimationClipを登録し、条件に合う表情へ切り替え |
| VRのコントローラー操作で手の形も切り替える | 初期値ON。ハンドサイン表情を有効にした場合に表示。VRのSteamVR Oculus/Meta Touch入力で表情と手形を切り替え。PCはShift＋数字キーを使用 |
| メニューから表情を変えられるようにする | 初期値OFF。名前とAnimationClipを登録し、Resonite上で選んだ表情を固定 |
| 標準サイズ | レンダラーの高さを基準に1.8mへ調整 |
| 元アバターのサイズ | シーン上のスケールを維持 |
| 現在のポーズと表情で固定 | SkinnedMeshRendererを現在の変形結果でベイクし、静的メッシュに変換。揺れ物は停止 |
| Modular Avatarを反映 | 導入済みなら一時コピーで前処理し、Bone ProxyやMerge Armatureの配置・追従を反映 |

## PhysBoneの角度制限

v0.3.2では、VRC PhysBoneに設定された次の角度制限をResoniteの標準コンポーネントで構成します。ツール側で制限を入力し直す必要はありません。元のPhysBone設定を読み取るにはVRChat SDKが必要ですが、SDKを入れていないUnityプロジェクトでもツール自体は使用できます。

| VRCの設定 | 変換後の動作 |
| --- | --- |
| None | 角度制限を付けない |
| Angle | 元の軸からの傾きを `Max Angle` の範囲に制限 |
| Hinge | 指定した軸の平面内で、設定角度の範囲に制限 |
| Polar | `Max Angle X`／`Max Angle Z` のそれぞれの範囲に制限 |
| Limit Rotation | 制限軸の向きを反映。XYZ各軸のカーブもボーンごとに適用 |
| 角度カーブ | ボーンごとに角度をサンプリングし、根元と先端で異なる制限を反映 |
| Ignore Other PhysBones | 別PhysBoneのRoot以下を対象から除外し、同じ骨への重複適用を防止 |
| Multi Child Type | Firstは最初の子の方向、Averageは子の平均方向を使う。Ignoreは分岐点自体を揺らさず、配下の対象ボーンを処理 |

VRCの `Endpoint Position` は反映しますが、Unityにない末端をResoniteがさらに自動延長する処理は停止します。別PhysBoneを除外した結果などで対象が1ボーンだけになり、`Endpoint Position` も0の場合、そのチェーンには揺れを発生させません。親のアニメーションや追従による移動は引き続き反映されます。

角度制限は**表示ボーン**へ適用します。衝突・つかみの計算は制限前の物理ボーンを使うため、限界角度付近で見た目と計算位置がずれる場合があります。また、ボーン階層に各軸で異なるスケールや負のスケールがある場合、ワールド空間での角度は近似になります。VRChatの揺れ方や衝突処理全体の完全再現は行いません。関連する警告は `.report.json` に記録します。

**変換対象のルートそのものを、角度制限付きPhysBoneのRootにした構成は出力できません。** この場合は理由を表示して変換を停止します。アバターやモデルのルート配下にある子ボーンをPhysBoneのRootに指定してください。Rootが未指定の場合は、そのPhysBoneコンポーネントを付けたオブジェクトがRootになります。

## 目の動きと影の濃さ

v0.3.1では、VRC Avatar DescriptorのEye Lookに保存された正面・上・下・左・右のボーン回転を変換します。上下を動かさない設定や小さい左右の可動範囲も保持します。視線の反応速度・注視先選択はResoniteの仕組みを使うため、VRChatの視線処理と完全に同じではありません。VRC側でEye Lookが無効なら目の自動回転を停止し、SDKがない場合はResonite標準の設定を使います。

「トゥーン影の濃さ」はlilToonとVRChat Mobile Toon Standardの影色を調整します。初期値は **0.5** で、変換する影色を弱めます。**1** は元の影色を基にした変換、**0** はトゥーン影色なしです。元マテリアルやテクスチャは変更しません。ワールドの照明、投影される影、テクスチャへ描き込まれた影をすべて取り除く設定ではありません。

VRChat Mobile Toon StandardはPBRではなくトゥーン材質へ変換します。通常瞬きと目閉じ表情が同じ顔の頂点を動かす場合は、表情の間だけ選択した通常瞬きを抑えます。単一の両目用瞬きShapeを選んだ場合、片目の表情との干渉でもそのShape全体を抑えます。

これらの修正は **v0.3.1以降で再変換した出力** に適用されます。以前の出力をコピーし直しても更新されません。

## ハンドサイン・メニュー表情

表情機能はアバター出力で利用できます。ハンドサインとメニューは別々のチェックで有効にし、どちらか一方でも併用でも設定できます。「3Dモデル・アイテム」では両設定が無効になり、出力に表情操作用の仕組みは付けません。

### 表情クリップとサンプル時刻

各項目の「表情アニメーション」にAnimationClip、「使用する時刻（秒）」にサンプル時刻を指定します。時刻の初期値は0です。出力するのは、その時刻における**BlendShapeの静止値**です。クリップを繰り返し再生したり、表情間の遷移を再現したりする機能ではありません。

- 対応するキーはSkinnedMeshRendererのBlendShapeです。Transform、材質、オブジェクトの有効・無効などのキーは対象外として警告します。
- 対象BlendShapeを1つも含まないクリップや、参照先のRenderer・Shapeを解決できないクリップでは変換を停止します。変換対象のルートを基準とするクリップを使用してください。
- Modular Avatarの前処理で階層が変わる場合に備え、処理前の参照先を一時コピー上で保持して処理後の対象へ対応付けます。処理によって参照先が失われた場合は、警告を確認してクリップや対象を見直してください。
- クリップが指定したShapeだけを表情値で固定します。指定していないShapeの口パクは維持します。瞬きと同じ頂点を変形する別の目閉じ・ウィンク等のShapeが有効な間は、通常の瞬きを抑え、解除すると再開します。選択した瞬きShapeへの正の値は表情として優先し、初期値0・クリップ値0のニュートラルキーは通常瞬きを妨げません。

### ハンドサインから切り替える

「両手の形に合わせて表情を変える」を有効にし、「ハンドサインの表情を追加」で行を追加します。各行で左手・右手の条件、AnimationClip、サンプル時刻を指定します。条件はVRChat形式の `Idle（自然な手）`、`Fist（握り）`、`Open（開き）`、`Point（指差し）`、`Victory（ピース）`、`RockNRoll（ロック）`、`HandGun（指鉄砲）`、`ThumbsUp（サムズアップ）` の8種と「指定なし（どの形でも）」（Any）です。Anyはその手の形を条件にしない指定です。

左右両方の条件を満たす行を選びます。複数行に一致すると上の行を優先するため、片手や両手をAnyにした広い条件は下に配置してください。「上へ」「下へ」で優先順を変更できます。どの行にも一致しない場合は初期状態へ戻ります。

### PCでキー操作から切り替える

v0.3.3以降で「両手の形に合わせて表情を変える」を有効にして書き出すと、PCでは左Shift＋数字キーで左手、右Shift＋数字キーで右手を操作できます。キーボード上段の数字1～8を使います。VRのコントローラー操作のチェック状態には影響されません。

| 数字キー | 手形 |
| --- | --- |
| 1 | Idle（自然な手） |
| 2 | Fist（握り） |
| 3 | Open（開き） |
| 4 | Point（指差し） |
| 5 | Victory（ピース） |
| 6 | RockNRoll（ロック） |
| 7 | HandGun（指鉄砲） |
| 8 | ThumbsUp（サムズアップ） |

Shiftと数字を押している間だけ指定した手の形と表情を使い、いずれかを離すと解除します。操作していない側の手は、表情の条件判定ではIdleとして扱います。どちらの手もキー操作していない間は、Anyの行を含めてハンドサイン表情を発動しません。PCのジャンプ・ダッシュなどに伴う指の変化から表情が選ばれることもありません。

数字を複数同時に押した場合は小さい番号を優先します。左右のShiftを同時に押すと、両手に同じ数字の手形を適用します。

メニューで固定した表情を優先します。キーを離してもメニューの固定は解除されず、「ハンドサインに戻す」でキー操作による表情を再開します。アイテムやツールを保持中の手は元の握り方を維持します。チャットなどの文字入力中はキー操作による切り替えを停止します。

反映するには元のUnityシーンから再変換が必要です。標準F2・F5・F6の編集・カメラ操作との競合を避けるため、Fキーは使用しません。ワールドやカメラに独自の数字キー操作がある場合、それらも同時に反応することがあります。

### VRのコントローラー操作で手の見た目も切り替える

「両手の形に合わせて表情を変える」を有効にすると、その下に「VRのコントローラー操作で手の形も切り替える」が表示されます。このチェックの初期値はONです。ハンドサイン表情自体の初期値はOFFのため、ツールを追加しただけで手の動きが変わることはありません。

SteamVRのOculus/Meta Touchでは、トリガーへの接触と押し込みを区別し、グリップ、親指の接触と組み合わせて8種のハンドサインを判定します。判定した手形を表情条件に使い、手指の見た目も8種のポーズへ切り替えます。表情クリップのTransformキーから指の形を移植する機能ではありません。

| 手形 | グリップ | 人差し指 | 親指 |
| --- | --- | --- | --- |
| Idle（自然な手）の例 | 離す | トリガーに触れるだけ | スティック／ボタンに触れる |
| Fist（握り） | 握る | トリガーを引く | スティック／ボタンに触れる |
| Open（開き） | 離す | トリガーから離す | スティック／ボタンから離す |
| Point（指差し） | 握る | トリガーから離す | スティック／ボタンに触れる |
| Victory（ピース） | 離す | トリガーから離す | スティック／ボタンに触れる |
| RockNRoll（ロック） | 離す | トリガーを引く | スティック／ボタンに触れる |
| HandGun（指鉄砲） | 握る | トリガーから離す | スティック／ボタンから離す |
| ThumbsUp（サムズアップ） | 握る | トリガーに触れる（引いても可） | スティック／ボタンから離す |

[VRChatのTouch操作表](https://docs.vrchat.com/docs/touch)を参考にしています。Idleの行はこのツールでの代表例です。

- 指をトリガーに置くだけの状態と、トリガーを引いた状態は別です。FistやRockNRollは押し込みを使い、ThumbsUpはトリガーに触れた状態を使います。その他の条件と合わない組み合わせはIdleになります。
- 親指はスティックやA/B/X/Yボタンへの接触、またはそれらの押下から判定します。ThumbRestへの接触は判定に使いません。VRChatのバインド設定そのものを取り込む機能ではありません。
- アイテムを握っている手やツールを使用中の手は、その操作に必要な元の握り方を優先します。
- メニューで顔の表情を固定しても、手形はコントローラー操作に追従します。
- チェックをOFFにすると、手指の見た目は元の制御に任せ、現在の指の姿勢から表情条件を判定します。

**Viveのトラックパッドから8種を選ぶ操作は未対応です。** Viveやその他のコントローラーは現在の指の姿勢から近似判定する方式を使い、この機能による手形の生成は行いません。そのため、すべての機器で全8種をボタン操作から出せることは保証しません。機器やバインド設定、指の曲げ方によって認識が異なる場合があります。

Resoniteエンジン内でコントローラー入力と手形生成を検証しています。VR機器を装着した実操作と、別PC間のネットワーク越しの表示は未確認です。

### メニューから固定する

「メニューから表情を変えられるようにする」を有効にし、「メニューの表情を追加」から表示名、AnimationClip、サンプル時刻を登録します。有効な項目が1件以上ある場合にResoniteの「表情」メニューを作り、「初期状態」を自動追加します。項目を登録しなければ表情メニューは作りません。

「初期状態」は、変換時にModular Avatarの前処理を反映したモデルのBlendShape値を基準に生成します。すべてのShapeを0にする操作ではありません。表情で上書きしない瞬き・口パクは引き続き動作します。

メニューから選んだ表情と「初期状態」はハンドサインより優先して固定します。両機能を有効にした場合だけ「ハンドサインに戻す」を追加し、これを選ぶと現在の左右の手形による切り替えを再開します。固定中に手形を変えても、固定した表情は変わりません。固定の対象は顔のBlendShapeで、手指の形は固定しません。

## 互換性と制限

- PhysBoneはResoniteのDynamicBoneChainへ近似変換します。Pull、Spring、Stiffness、Gravity、Immobileの基本値を、チェーン全体の弾性・減衰・硬さ・重力・慣性へ換算します。VRCとResoniteは別の物理計算を使うため、同じ揺れ加減を再現するものではなく、取り込み後の調整が必要になる場合があります。
- PhysBoneの対象ボーン、除外ボーン、末端オフセット、半径と半径カーブを反映します。Pullなどのボーンごとのカーブはサンプリング値をパッケージ内の参照情報へ記録しますが、Resoniteの各ボーンの物理係数としては適用しません。元のUnityシリアライズ値も `.report.json` に記録します。
- PhysBoneのAngle／Hinge／Polarは上記の方式で表示ボーンへ適用します。Gravity Falloff、Stretch / Squish、計算モード、Animatorやパラメーターによる動作変更は再現しません。球コライダーを移し、カプセルは複数の球で近似します。平面・内側拘束・半径0のコライダーは省略して警告します。VRCの相手別の衝突・つかみ許可やCollision Tagsも同じ意味では移植されません。
- lilToonはResoniteのXiexeToon材質へ変換します。色、テクスチャ、透過、法線、発光、影、輪郭など対応する要素を移し、一部はテクスチャへ焼き込みます。独自シェーダーコードや全特殊効果は移せません。
- Modular Avatar導入時はNDMFの前処理を一時コピーへ適用し、Bone ProxyやMerge Armatureによる配置・統合の結果を通常のボーン階層・メッシュとして出力します。両コンポーネントの追従と元シーンを変更しないことをテストしています。NDMFが利用できない場合の代替処理は、Bone ProxyとMerge Armatureの基本的な追従だけに限定し、未適用のMAコンポーネントを警告します。
- 既存のVRChat / Modular AvatarのExpression MenuやAnimatorの操作ロジック、VRChatのContacts、独自スクリプトはResonite用ロジックへ自動変換しません。新しい表情機能では、このツールに登録したクリップの静止値から独立した操作を作ります。VRC Constraintは書き出し時点のTransformを出力し、Resonite上で制約による追従を再計算しません。静的な小物にする場合は「現在のポーズと表情で固定」を使用してください。
- 1頂点に5本以上のボーンが影響するメッシュは、Resonite出力で上位4本へ重みを正規化し、警告します。選択ルート外のボーンに依存するメッシュは、アバター全体を対象にするかポーズ固定を有効にしてください。
- 削除されたパッケージに由来するMissing Scriptの設定は復元できません。未導入でもツールは動きますが、元設定の読み出しには元コンポーネントが必要です。
- 保存制限はResonite標準コンポーネントの挙動を利用します。暗号化やデータの複製そのものを防止する仕組みではありません。自分のインベントリへの保存後、別ユーザー視点で動作を確認してください。
- 変換結果と並ぶ `.report.json` に警告を記録します。詳細ログはUnityプロジェクトの `Library/BEPFairyTech/ResoConverter/Runs` にあります。
- Resonite本体の更新で内部APIが変わる場合は、変換エンジンの更新が必要になります。
